## Page System

### Part 1 — Objective Items

- A4 portrait.
- Header/opening block: one column, margins 0.50 in on every side.
- Objective content: a continuous section with **two native Word columns**;
  keep page margins at 0.50 in and column gap at 566 twips (0.393 in).
- Let Word fill the left column then the right column automatically. Do not use a
  table to simulate columns and do not insert manual column breaks.
- Use no global divider rule between columns unless the teacher explicitly asks;
  the reference's XML uses native column settings without a `w:sep` flag.

### Part 2 — Written Items

- Start on a fresh page.
- Return to one native Word column with 1.00 in margins.
- Use dotted answer lines at about 1.15 line spacing, with no added paragraph
  after-spacing, so the response area stays regular and print-efficient.

## Type And Rhythm

- Thai prose and Thai question/choice labels: `TH Sarabun New` 16 pt through the
  Complex Script route.
- Mathematical and logic notation: editable inline OMML; keep Thai prose outside
  OMML.
- Question number: bold, Thai-styled 16 pt label.
- Objective paragraphs: single line spacing and 0 pt before/after spacing.
- The paper is intentionally compact. Do **not** add blank paragraphs between
  ordinary items. The end of choice 4 and the start of the next question are
  separated by one ordinary line rhythm only.

## Question Block Pattern

Each objective item normally has two paragraphs:

1. Stem paragraph: question number plus prompt; use a hanging indent so wrapped
   lines align with the prompt text, not under the question number.
2. Choices paragraph: all four choices in one paragraph, separated by deliberate
   manual line breaks. This keeps the choices reading as one compact block.

Use a hanging indent of roughly 0.20 in for one-digit question labels and 0.28 in
for two-digit labels. Choices are normally inset about 0.20 in. The default choice
layout is four vertical lines. Use a 2-by-2 arrangement with a tab stop only when
all four choices are genuinely short, especially compact symbolic choices.

## Line-Break Rules

Hard line breaks are meaningful layout tools, not automatic decoration.

- Split definitions of `p`, `q`, `r`, etc. into separate lines when that makes the
  symbolic statement below easier to scan.
- Put a long displayed logic formula on its own semantic line when it would make
  the prose line hard to read.
- In multi-part truth-value questions, put ก/ข/ค on distinct lines.
- In argument-validity questions, lay out ก/ข, each premise, and the conclusion
  as a compact structured stack. Do not compress all premises into a dense prose
  sentence.
- Do not force long choice text to wrap casually. Prefer a semantic break in the
  stem or a different layout profile before accepting an awkward wrapped choice.

## Last-Mile Fit Adjustment

The page margin is not adjusted globally for one awkward item. When a stem is
nearly one line too long and would leave an orphan word, use this order:

1. Check whether a semantic manual line break would improve reading.
2. If the line is otherwise good, apply a **question-local negative right indent**
   to gain a small amount of usable width.
3. Keep the exception small, usually about 0.10–0.30 in, and verify the item in
   Word. Do not reduce the body font size to solve a single orphan line.

This is intentionally a per-item override. Future generators should support a
layout profile and a `right_extension` value for individual questions rather than
changing the whole paper's margins.

## Reusable Layout Profiles

| Profile | Use when | Layout action |
|---|---|---|
| `normal` | Short or medium stem, ordinary choices | Stem + four vertical choices |
| `definitions` | Several variable definitions before a symbolic sentence | One semantic line per definition, then statement + choices |
| `two_by_two` | Four short choices | Two rows of two choices using a tab stop |
| `multi_statement` | ก/ข/ค truth statements | One line per statement, then ordinary choices |
| `arguments` | Paired validity arguments | Compact premise/conclusion stack for ก and ข, then choices |
| `long_stem` | Near-orphan wrap | Semantic break first; local right-extension only if needed |
