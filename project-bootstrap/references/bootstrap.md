# Bootstrap and adoption

## Inspect before writing

1. Confirm the supplied project root using filesystem evidence. Read its exact
   instruction entrypoint and named current route. No recursive inventory.
2. Separate persistent project knowledge from the current work object's contract,
   state and history. Register existing roles before inventing new files.
3. Inspect actual environment facts if the request needs them: a known package
   manifest, test configuration or existing command reference. Missing Git/npm is
   not an error; Apps Script/manual verification and documents are valid projects.
4. Present a compact create/update/no-change plan with each authoritative source.
   Proceed with reversible setup already requested by the user; ask only for a
   real semantic conflict or missing root/ownership decision.

## Empty root

Seed only what is known. A short owned AGENTS block can hold the stable project
purpose and a pointer to the next design step. If Claude is used, a thin CLAUDE.md
points to that same authority; it does not copy the rules. Do not invent test
commands, approval, code directories or an entire control bundle. The next action
may be 'continue design'. Grill owns its decision ledger once the problem locks.

Do not create project-context.json just to complete a checklist. Add it once
concrete roles/routes need machine checking and no supported adapter already owns
that routing. Schema is in schema.md. Its values are pointers, not copied state.
Point at owned marker blocks rather than heading text wherever the file is edited
often; a renamed heading breaks a section pointer silently.

## Existing project

Adopt existing owners, including STATE + PROJECT_MAP and document topic indexes.
Use generic bindings when the existing convention is not supported by the control
adapter. A project that already ships its own context helper (for example a
`scripts/project_context.py` with `start`/`ticket`/`lookup` commands) keeps that
helper as its route: bind to the files it reads, do not add a same-named script,
and do not ask sessions to run both. Preserve project behavior and all unowned text; add only the missing
entrypoint/bridge or route. An existing map remains canonical. Derived readable
mirrors must be declared and checked; ordinary links are references, not mirrors.

Do not read a large source wholesale merely to generate configuration. Choose
exact sections from the known entrypoint and the user's task. A missing legacy
path gets one targeted lookup or an explicit unresolved note, not a whole-tree
search. Two different scoped projects may have different state owners.

## Safe agent edits

Use stable markers `<!-- project-bootstrap:SCOPE:start -->` / `:end` around owned
blocks. Before editing, capture the current file hash and intended owned diff.
Immediately reread the file/hash before applying the edit. If changed, recompute
against the new text; never restore the old full file. Preserve line endings,
unowned lines, unrelated dirty content and existing authority. Do not delete an
existing file or rewrite a user's convention to make the helper pass.

One fact, one owned block. When the same current claim would appear in several
files, keep one owner and make the others pointers or declared mirrors; undeclared
copies drift and check cannot see them.
Missing/malformed/duplicate markers are an ambiguity: report the exact block and
repair only with a concrete scoped interpretation. For an interrupted first run,
inspect what landed, validate existing targets, and finish only missing steps.
Create a referenced target before its pointer. A rerun with unchanged inputs must
produce no diff, including timestamps: record `blocks --root <root>` output before
and after the rerun and compare the hashes; that table is the idempotence evidence. No 'ready' claim until required routes
resolve. Keep a recoverable scoped preimage; never snapshot unrelated user data.

## Phase enrichment

After grill establishes real contracts and verification, bind those exact
sources. For a new Mode L build the normal Project Map lives in BUILD-CONTROL.
For adoption, preserve a functioning existing project map and state owner;
link staged work to them instead of duplicating current truth. See integration.md.

At completion retire the active work pointer and retain project knowledge plus
completed contract/history routes. A new task does not implicitly reopen finished
work. Snapshot/handoff dates are historical evidence, not authority rankings.

## Acceptance exercise

Run inspect/check, then a fresh context route for a realistic next action.
Check goal, effective scope/approval or unknown, next step, relevant constraints,
source files and verification. Rerun the requested setup and inspect the diff.
For an agent-owned writing workflow, CLI tests alone cannot prove idempotence or
concurrency safety: evaluate the actual edits and before/after hashes.

## Generic/document route

A generic project may map design, production and archived work separately. A
supplied snippet with no named project can require zero repository reads. Design
should not preload production/render manuals; read them when production is
actually requested. Treat image/render/token ratios from an example as local
observations, never universal defaults. No code/test/control scaffolding is needed
merely to prove generic routing.
